# MIND 评测子模块 PRD

> 立项日期：2026-08-17 ｜ 版本：v0.2（已确认设计）
> 定位：MIND 记忆系统的正式子模块，用真实工作环境评测「模型 × MIND」的工作能力。

---

## 1. 问题陈述

1. **benchmark 虚高**：通用 benchmark 分数高，但真实工作环境（多轮迭代 + 长任务压缩）表现不确定。
2. **无法量化 MIND 的价值**：MIND 记忆系统提高模型多少工作能力，没有客观数据。
3. **新模型发布无快速评估**：不知道新模型在真实任务上能拿多少分。

## 2. 目标与定位

用 pi agent harness + 真实任务改造的难任务 + 多轮用户对话 + 长任务压缩，测 `{模型} × {有/无 MIND}` 的真实工作能力，产出「完成度 / 机会次数消耗 / 成本」得分表（落文件）。

## 3. 目标用户 + 典型场景

**用户**：独立开发者（8GB Mac，Python/Rust，Claude Code + MIND）。

**场景**：新模型发布 → 跑 `bench-run --models X,Y --tasks all` → 每格在 Docker 沙箱里多轮对话（机会次数内）→ 得完成度 + 成本 → 决策。

## 4. 功能清单

### P0（核心闭环）
- **评测矩阵**：`{模型} × {有/无 MIND} × {5 任务}` 全组合调度，每格独立沙箱
- **MIND 注入**：有 MIND = 全局记忆注入 pi system prompt（`appendSystemPromptOverride`）；无 MIND = 通用非 MIND 提示（纯净对照）
- **多轮对话 + 机会次数**：任务按难度分级 **A=1 次 / B=2 次 / C=3 次**；每轮跑「业务测试 + 回归测试」双层检查点，两层都过 = 完成；次数用尽未完成 = 失败（记录未收敛）
- **任务描述原则**：给「现象 + 可运行测试」，**不给根因提示**（如 1 万字符 bug 不说"是字符不是字节"，靠推理定位）
- **全自动验证**：检查点全是脚本机械判定（业务 + 回归），**不需要人工反馈**
- **Docker 沙箱**：隔离工作区（只拷任务代码）、禁联网，防跑出工作区作弊
- **成本统计**：每格记录 token；**v4f 输出峰/谷两个价成本**，其他模型单一价
- **得分表输出**：落文件（Markdown + CSV，含 MIND 增益 + 模型差异对比）

### P1
- 任务集管理（5 任务，难度分级，双层检查点，反馈序列）
- MIND 注入内容管理（从记忆文件生成）

### P2（暂不做）
更多模型、UI、定时评测、增量评测。

## 5. 不做清单

- 不做通用 benchmark（已有）
- 不做模型训练/微调
- 不做 UI/看板（CLI + 文件）
- **不做需要人工视觉/效果反馈的任务**（如前端 UI、渲染效果——检查点必须脚本可判）
- 不做真人实时模拟（只预设反馈）
- 不接入 MIND 看板

## 6. 成功指标（可验证）

1. 评测可跑通：16 次基础运行（4 配置 × 5 任务）≤2 小时，无环境崩溃
2. 得分表有区分度：≥3/5 任务上，有/无 MIND 的完成度或次数消耗有 ≥1 档差异
3. 可复现：同配置同任务跑 2 次，完成度差异 ≤1 档
4. 成本可控：单次完整评测（16 格）token 成本在预算内（预估 ¥20-60）
5. 可复用：新增模型加一行配置即跑

## 7. 约束与风险

| 约束/风险 | 说明 |
|---|---|
| 低内存 Mac | 串行跑，每格独立 |
| pi 生态 | TS/npm 包，runner 需 Node；pi 无内置沙箱（Docker 补）|
| API key | 已存 `~/.mind-bench/apikeys.env`（chmod 600）|
| 任务难度 | 若任务太简单测不出 MIND 增益，重选 |
| MIND 注入长度 | 全量注入可能超 pi prompt 限制，需评估 |
| 长任务成本 | 跑前预算，超预算中断 |
| 峰谷定价 | v4f 成本按峰/谷分别统计（用户错峰优化参考）|

## 8. 待确认项（进入实现前）

- 任务 "够长到多次 compact" 的判定（实现时实测每个任务触发 ≥2 次压缩）
