## 2. 已定位并修复的问题

### 2.1 注入上限是硬编码的

原实现：

- 快照 12,000 字符上限
- 规则 60 条上限
- 标题 80 字、结论 240 字截断
- 日报只注入固定条数

处理：

- 删除 12,000 字符上限、60 条规则上限、80/240 字截断。
- 项目规则全量注入。
- 月报全部历史、全文注入。
- 日报改为连续 21 天窗口，结束于 7 天前。
- turns 使用 `turnSummaryChars` 预算，默认 100,000 字符；溢出按天聚合，不逐条堆叠。

### 2.2 快照每轮重复追加

原行为：

- 快照包含最近 7 天 turns；新 turn 产生后快照变化，DSH 把整份 60K 左右的记忆重新追加为新的 user 消息。
- 会话缓存命中率被拖低。

处理：

- 快照按 session 生成一次并缓存。
- 今天的 turns 不进入快照，改由每轮增量补。
- turns 摘要段只注入 `status='current'`；`invalid` 不进入摘要段。
- 各段改为旧 → 新排序，稳定前缀。

### 2.3 迁移的日报/月报原文被 DSH 重建覆盖

原因：

- `rebuildDayIndex` / `rebuildMonthIndex` 会用 turn 列表重新生成日报/月报，覆盖迁移进来的旧正文。

处理：

- 从旧 `nailong.db` 恢复：
  - 277 组日报（旧库 281 条，重复项目合并）
  - 21 组月报（旧库 25 条，重复项目合并）
- 逐条校验：旧正文全部包含在恢复后的文件中，0 缺失。
- 加保护标记：
  - `day_index.root_id='legacy'`
  - `period_index.legacy_synthesized=1`
- 视图重建遇到 legacy 日报/月报只更新索引计数，不再重写正文。
- 重启后复验：日报 277/277、月报 21/21 全部保留。

### 2.4 摘要队列堵塞

原行为：

- 旧 turn 的摘要任务大量积压。
- 部分任务反复报 `summary returned no valid JSON`。
- 一个任务失败会阻塞后续任务。

排查结果：

- 待处理 turn 在旧 MIND 库中都对应 `invalid` 或 `merged` 记录，没有有效摘要可复制。
- 这些 turn 本身是噪音/已合并，不需要再让 LLM 摘要。

处理：

- 摘要功能改为默认关闭：`summarizeEnabled=false`。
- 已摘要的 `current` 记录保留。
- 未摘要记录统一标记 `status='invalid'`。
- 后台 pending/running 任务全部结束。
- 当前状态：
  - `current`：15,029
  - `invalid`：8,980
  - 后台任务：0 pending / 0 running

### 2.5 当天日报缺失

原因：

- capture 热路径只更新 `day_index` 的标题和计数，不生成日报文件。
- 摘要未完成时，`days/YYYY-MM-DD.md` 不存在。

处理：

- 缺失日报在 ingest 后立即重建。
- 启动时也会扫描 `report_rel_path` 为空的日期并补齐。
- 2026-10-25 日报已生成并写回 `day_index`。
